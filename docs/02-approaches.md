# 02. 만들 수 있는 형태

같은 엔진을 어디에 붙이느냐에 따라 쓰는 속도가 달라진다. 기능은 같고, **손이 가는 횟수**가 다르다.

혼자 쓰고, 유튜브는 폰으로 보는 전제다.

## 한눈에 비교

| 형태 | 폰에서 | 구현 난이도 | 유지비 | 유튜브로 넘어가기 | 추천 |
|---|---|---|---|---|---|
| A. 텔레그램 봇 | 즉시 | 낮음 | 거의 0 | 링크 탭 | **1순위** |
| B. 모바일 PWA | 홈화면 앱 | 중간 | 도메인+호스팅 | 링크 탭 | **2순위, 같이** |
| C. 텔레그램 미니앱 | 텔레그램 안 풀스크린 | 중간~높음 | 낮음 | 좋음 | 봇이 답답해지면 |
| D. Cursor MCP | 폰에서 불가 | 낮음 | 0 | 나쁨 | 보조 |
| E. n8n / Make 자동화 | 알림은 됨 | 낮음 | 구독 | 보통 | 엔진을 직접 쓰기 싫을 때 |
| F. 카카오 챗봇 | 카톡에서 | 높음 | 검수 | 보통 | 비추천 (혼자 쓰기엔 과함) |
| G. 네이티브 앱 | 앱 아이콘 | 높음 | 스토어 | 가장 좋음 | 나중 |
| H. CLI + SSH/Termux | 가능하나 불편 | 낮음 | 0 | 나쁨 | 개발용만 |
| I. 노션/이메일 다이제스트 | 읽기만 | 낮음 | 0 | 보통 | 아침 요약용 보조 |

## A. 텔레그램 봇 — 1차로 이걸 만든다

입력: 채팅창에 키워드.  
출력: 브리핑 메시지 + 영상별 인라인 버튼.

왜 1순위인가:

- 폰에 이미 있다
- 유튜브 링크를 누르면 유튜브 앱이 열린다
- 프론트엔드를 안 만들어도 오늘 쓸 수 있다
- 나중에 영상을 봇에게 공유해서 “이 영상만 요약”도 된다
- 푸시가 공짜다. 관심 키워드를 저장해 두면 아침 다이제스트를 보낼 수 있다

한계:

- 긴 브리핑은 스크롤이 길다
- 스탠스 비교 표는 웹이 더 낫다
- 텔레그램을 안 쓰면 의미가 없다

혼자 쓸 때의 운영:

- BotFather로 봇 하나
- 본인 `user_id`만 allowlist
- 웹훅은 작은 VPS 또는 Cloudflare Tunnel

이게 **가장 빨리 “폰에서 써보는”** 길이다.

## B. 모바일 PWA — 본편 UI

Safari/Chrome에서 열고 홈 화면에 추가한다. 앱스토어가 필요 없다.

잘 맞는 화면:

- 키워드 검색창
- 합의 / 갈림 칩
- 기사·영상 카드
- 필터: 기간, 언어, 대형만 제외, 숏츠 제외
- 이미 본 영상 숨기기

iOS 제약:

- 푸시는 제한적이다. 알림이 필요하면 텔레그램을 유지한다
- 홈 화면 추가는 수동이다

**추천 조합: 봇으로 받고, 자세히 볼 때만 PWA를 연다.**  
봇 메시지에 `웹에서 보기` 버튼 하나만 있으면 된다.

## C. 텔레그램 미니앱

텔레그램 안에서 PWA를 연다. 봇과 웹을 한 앱처럼 붙일 수 있다.

인터페이스는 B와 같고, 배포만 텔레그램 WebApp이다.  
1차를 봇+PWA로 만든 뒤 껍데기만 씌우면 된다. 처음부터 미니앱을 목표로 두지 않는다.

## D. Cursor MCP / CLI

엔진을 MCP 툴로 노출하면 Cursor 채팅에서

`미국 국채 금리 최근 의견 지도 만들어`

가 된다. 설계·문서 작업에는 좋지만, **영상을 폰으로 보는 습관과는 반대**다.

위치: 보조. 엔진 JSON을 그대로 감싸면 하루면 된다.

## E. n8n / Make / Zapier

코드 없이 대략은 된다.

예:

1. 텔레그램 트리거
2. YouTube 검색 (공식 또는 HTTP)
3. 뉴스 RSS
4. LLM 노드
5. 텔레그램으로 회신

장점: 빨리 흉내 낸다.  
단점: 다양성 규칙, 자막, 스탠스 클러스터, 캐시, 실패 복구를 제대로 넣기 어렵다.  
“쓸 수 있는 것”과 “정확한 의견 지도” 사이에는 거리가 있다.

판단: **프로토타입 하루용**. 본 저장소의 본체로 쓰지 않는다.

## F. 카카오톡

한국 폰 UX는 카톡이 맞다. 다만 챗봇 빌더·비즈니스 채널·검수가 혼자 쓰기엔 비용이 크다.  
카톡 공유는 나중에 “결과 링크 공유” 정도로만 둔다.

## G. 네이티브 앱 (Expo / Swift)

유튜브 앱 연동, 위젯, 공유 시트까지 가려면 결국 여기로 온다.  
스토어 심사와 유지비가 1인 도구에 안 맞는다. PWA가 답답해지면 Expo로 같은 API를 감싼다.

## H. 이미 있는 서비스를 이어 붙이기

직접 만들기 전에 쓸 수 있는 것:

| 조합 | 되는 것 | 안 되는 것 |
|---|---|---|
| Perplexity + 유튜브 수동 | 기사 종합 | 최근 영상 다양성 |
| YouTube Premium + 메모 | 한 영상 | 탐색 자체 |
| Notion AI + RSS | 기사 보드 | 영상 자막·스탠스 |
| Glasp / 요약 확장 | 지금 보고 있는 영상 | 키워드 → 여러 영상 |

이어 붙여도 **키워드 → 다양한 최근 영상 의견**은 빈다.  
그래서 엔진은 직접 만드는 편이 맞다. UI만 기존 메신저를 빌린다.

## 추천 결정

```text
지금 만들 것
  Telegram bot  ← 오늘부터 폰에서 사용
  engine        ← 수집·자막·의견 지도
  sqlite 캐시

바로 이어서
  모바일 PWA    ← 같은 API

나중에
  MCP, 아침 다이제스트, 미니앱, Expo
```

형태를 여러 개 동시에 키우지 않는다. 엔진 한 개, 창구 두 개(봇+웹)면 충분하다.
