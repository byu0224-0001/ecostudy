# 01. 큰 그림

입력은 키워드 하나다. 출력은 “요즘 이 주제를 누가, 어떤 근거로, 어떻게 다르게 말하는지”다.

검색창을 하나 더 만드는 것이 아니다. **같은 키워드를 여러 경로로 펼치고, 출처를 섞고, 의견을 묶어서** 한 장의 브리핑을 만든다.

## 사용자가 하는 일

폰에서:

1. `미국 국채 금리` 입력
2. 기간을 고른다. 기본은 **최근 14일**
3. 2~4분 뒤 브리핑을 읽는다
4. 의견이 갈리는 영상만 유튜브 앱으로 연다

PC·Cursor에서도 같은 엔진을 부를 수 있게 두면 이후 MCP나 CLI는 공짜로 생긴다.

## 파이프라인

```text
키워드
  │
  ├─ 1. 쿼리 확장
  │     미국 국채 금리
  │     US 10Y treasury yield
  │     국채 발행 / 재정 적자
  │     Fed / 금리인하 경로
  │
  ├─ 2a. 기사·칼럼 수집          2b. 유튜브 수집
  │     네이버 뉴스                최근 업로드 검색
  │     Google News RSS            채널당 상한
  │     영문 검색 API              숏츠/본편 분리
  │     지정 RSS (한경, WSJ …)     구독자 버킷 섞기
  │
  ├─ 3. 본문·자막 추출
  │     기사: 원문 추출 (실패하면 스니펫)
  │     영상: 자막 → 없으면 스킵 또는 후순위 Whisper
  │
  ├─ 4. 주장 추출
  │     각 출처에서
  │       - 핵심 주장 1~3개
  │       - 근거 (숫자, 이벤트)
  │       - 스탠스 (상승/하락/중립/조건부)
  │       - 신뢰 힌트 (1차 자료 인용 여부)
  │
  ├─ 5. 의견 지도
  │     합의점
  │     갈린 지점
  │     소수 의견
  │     빠진 각도 (아무도 안 말한 것)
  │
  └─ 6. 모바일 브리핑
        한 화면 요약
        기사 카드
        영상 카드 + 유튜브 딥링크
```

한 단계라도 검색 결과 덤프가 되면 실패다. 5번이 제품이다.

## 한 번의 검색이 만들어야 하는 산출물

예시 키워드: `미국 국채 금리`

```text
기간: 최근 14일
쿼리: 미국 국채 금리 / US 10Y / 장기금리 / 국채 발행

■ 한 줄
10년물 금리가 다시 들렸다는 관측은 거의 같고,
원인이 재정 수급인지 인플레 재가속인지는 갈린다.

■ 합의
- 10년물 레벨이 최근 박스권 상단 근처다
- 단기 이벤트: 입찰 / CPI / FOMC 의사록

■ 갈림
- A. 재정·발행 물량이 커브를 밀어 올린다
- B. 디스인플레가 멈춘 것이다
- C. 레벨보다  termin 프리미엄이 문제다

■ 기사 6
  한경 · 매경 · FT · Bloomberg · 개인 칼럼 1
  각 카드: 매체 / 날짜 / 스탠스 / 한 줄 / 원문 링크

■ 영상 8  (채널 중복 없음)
  대형 2 · 중형 3 · 소형/영문 3
  각 카드: 채널 / 게시일 / 길이 / 스탠스 / 핵심 3줄
  [유튜브에서 보기]
```

기사와 영상을 **같은 스탠스 축**으로 붙여야 한다. 기사만 따로, 영상만 따로 두면 종합이 아니다.

## 다양성 규칙

유튜브와 뉴스 모두 “위에 뜨는 것”이 통념이다. 그걸 그대로 가져오면 원래 문제로 돌아간다.

반드시 코드로 강제할 규칙:

1. **채널당 최대 1개** (같은 채널 최신만)
2. **매체당 최대 2개**
3. **쿼리를 한/영, 동의어, 원인 키워드로 나눈다**
4. **조회수순 정렬을 쓰지 않는다.** 최근성 + 채널 다양성 + 스탠스 커버
5. **구독자 버킷을 섞는다**  
   대형(100만+) / 중형 / 소형. 기본 비율 2:3:3
6. **숏츠와 본편을 분리한다.** 숏츠는 의견이 빈약하니 기본은 본편만
7. **자막 없는 영상은 목록에는 남기되, 요약 신뢰도를 낮춘다**
8. **같은 헤드라인 재전송은 하나로 합친다** (네이버 뉴스  syndicated 복제)

이 규칙이 검색 API보다 중요하다.

## 모듈 경계

형태(봇, PWA, MCP)와 엔진을 붙이지 않는다.

```text
apps/
  telegram-bot      폰 1차 UI
  web-pwa           폰 2차 UI
  mcp               Cursor용 (선택)
  cli               디버그

engine/
  expand            쿼리 확장
  collect_news
  collect_youtube
  extract           본문/자막
  claims            주장·스탠스
  map               의견 지도
  render            텔레그램/웹/JSON

store/
  sqlite            캐시, 브리핑 이력, 본 영상
```

나중에 카카오톡을 붙이든 n8n을 붙이든, `engine`은 그대로 둔다.

## 품질 기준

잘된 브리핑의 조건:

- 같은 말을 세 출처가 반복하지 않는다
- 반대 의견이 **최소 하나** 보인다. 없으면 “반대 의견을 못 찾았다”고 명시한다
- 모든 문장에 출처가 있다
- 숫자(금리 레벨, 날짜, 입찰 규모)는 모델이 지어내지 않고 원문에서 가져온다
- 영상 카드에서 유튜브를 **한 탭**에 연다

잘못된 브리핑의 증상:

- 상위 채널 요약 10개
- “전문가들은 ~라고 합니다” 식의 단일 서사
- 자막 없이 제목만 의역
- 6개월 전 영상을 최근인 것처럼 넣음

## 하지 않을 것 (1차)

- 자동매매, 시그널, 포트폴리오 추천
- 전체 영상 다운로드 보관
- 자막 전문을 외부에 다시 올리기
- 스터디 모임 운영 도구 (이전 프로젝트)
- 다사용자 로그인, 결제, 앱스토어 출시

혼자 쓰는 정확하고 빠른 의견 지도가 목표다.
