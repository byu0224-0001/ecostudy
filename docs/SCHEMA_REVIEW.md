# 스키마가 바뀌어 온 자취

무엇을 왜 고쳤나. 같은 실수를 두 번 하지 않으려고 남긴다.

## v1 — verify 문자열 하나

주장마다 `verify` 에 `"ecos"` 같은 문자열을 하나 받았다. 곧 한계가 왔다.
어댑터 여럿이 필요한 주장을 못 담고, "확인 못 함"과 "확인할 필요 없음"이
똑같이 `없음` 으로 뭉갰다.

## v2 — 유형과 대상 배열

`claim_type` 을 넣고 검증 대상을 배열로 바꿨다. `adapter_verifiable` 과
`researchable` 두 참/거짓을 뒀다. 앞은 "API 로 대조되나", 뒤는 "연구할
가치가 있나"였다.

**여기서 잘못 판단한 것이 있다.** 당시 나는 `researchable` 이 스터디 후보를
가르는 본질 기준이라고 봤다. API 로 대조 못 하는 정책·산업 얘기도 좋은
주제라는 생각 자체는 맞았다. 그런데 그 판단을 **주장 하나마다** 물은 게
틀렸다.

## v3 — 재보고 고친 것

14통 489건을 실측했다.

### researchable 은 아무것도 가르지 못했다

489건 중 481건이 참(98%)이었다. 유형별로 보면 더 분명하다.

| 유형 | True | False |
| --- | ---: | ---: |
| interpretation | 18 | 0 |
| forecast | 25 | 0 |
| opinion | 2 | 0 |
| causal_claim | 52 | 0 |

의견까지 전부 "연구할 만하다"로 나왔다. 거의 항상 참인 필드는 필드가 아니다.

문제는 **질문이 잘못된 것**이었다. "이걸 연구할 가치가 있나"는 주장 하나가
아니라 사건이나 주제 단위에서 답할 일이다. 주장 단위에서 물어야 할 것은
"이걸 **어떻게** 확인하나"이고, 그건 참/거짓이 아니라 경로의 문제다.

그래서 없애고 `verification_mode` 로 바꿨다. `direct_data` `primary_source`
`multi_source_research` `interpretive` `future_tracking` `not_researchable`.
이 값이 나중에 Verification Router 의 입력이 된다.

### source_span 100% 는 아무 뜻도 아니었다

"전부 채워져 있다"는 뜻이었을 뿐이다. 실제로 원문에 있는지는 안 봤다.
문자열 검색으로 대조해 보니 8건이 원문에 없었다.

그런데 지어낸 게 아니었다. 대부분 이런 모양이었다.

> "내년 1월부터는 퇴출 기준이 강화될 예정입니다. **...** 오는 10월에는 첫
> 퇴출 사례가 나올 가능성이 높습니다."

떨어진 두 문장을 `...` 로 이어 붙인 것이다. 조각은 각각 원문에 있으니
추적은 되지만, 그대로 옮기면 원문에 없는 문장이 만들어진다. 성격이 다르니
`fuzzy` 와 나눠 `stitched` 로 따로 센다.

`exact` 만 인용 가능으로 두고 `Item.quotable` 로 노출한다. 프롬프트에도
"떨어진 두 곳을 잇지 마라"를 넣었다.

### 주장이 늘어난 건 중복 때문이 아니었다

438 → 489. 같은 말을 두 번 뽑은 게 아닌가 의심했는데, 블록 안에서 겹치는
쌍은 3건뿐이었고 그중 둘은 오탐이었다. 코스피 6,579 와 코스닥 858 은
문장 틀이 같아 자카드가 높지만 서로 다른 사실이다.

진짜 원인은 다른 데 있었다. 블록당 주장 수 분포가 이랬다.

    1개: 21블록   2개: 21블록   3개: 109블록   4개 이상: 16블록

**167블록 중 109블록이 정확히 3개.** 프롬프트에 "0~3개"라고 써 둔 것이
목표치처럼 작동했다. 모델이 담긴 만큼 뽑은 게 아니라 세 개를 채웠다.

개수 지시를 지웠다. "블록에 담긴 만큼만" 으로 바꿨다.

한 가지 더 알게 된 것: 글자 겹침으로는 한국어 중복을 못 잡는다. "상승했다"와
"올랐다"는 글자가 하나도 안 겹친다. 그래서 이 점검은 **선별 장치일 뿐**이고
진짜 중복은 정답지의 `duplicate_of` 로만 셀 수 있다.

### 유형 합계가 안 맞았던 건 보고 오류

487 vs 489. 데이터는 멀쩡했고 내가 상위 8개만 출력했다. 9번째 `opinion`
2건이 빠져 있었다. 이제 자르지 않고 전부 찍는다.

작은 일이지만 남겨 둔다. 채점 자동화를 만들면서 이런 불일치를 그냥 넘기면
나중에 어느 숫자를 믿을지 알 수 없게 된다.

## 사건 묶기도 같이 고쳤다

이름표가 `지난달`, `기록했다` 로 나왔다. 불용어를 더 넣을 문제가 아니라
세 가지가 같이 틀려 있었다.

| 고친 것 | 왜 |
| --- | --- |
| 매체 2곳 이상 → 관문 폐지 | 한국은행 발표 하나로도 스터디는 열린다. 이제 confidence 의 재료 |
| 같은 날 → 3일 창 | 월요일 발언, 수요일 급등은 한 줄기다 |
| 토큰 겹침 → idf 가중 | 흔한 토큰은 무엇이든 묶어 버린다. 드문 토큰이 묶음을 정한다 |
| 이름표 = 씨앗 토큰 → 공통 희귀 토큰 셋 | 묶음 전체가 공유하는 드문 말이 사건을 드러낸다 |

그리고 **사건과 주제를 같은 것으로 취급하지 않기로 했다.** 알파벳 AI
회사채 발행과 메타 AI 설비투자는 같은 사건이 아니지만 같은 줄기다.

    주장 → 사건 → 줄기 → 스터디 주제

줄기 계층은 아직 안 만들었다. 다만 사건 판정을 참/거짓이 아니라
`same_event / related_theme / unrelated` 셋으로 설계해 자리를 비워 뒀다.
