# 주장 추출

뉴스레터 블록에서 **확인할 수 있는 형태의 주장**을 옮긴다. 요약이 아니다.

## 이 작업의 위치

여기서 나온 것은 전부 검증 대기 중이다. 뒤에서 데이터와 사람이 판정한다.
그러니 맞는지 틀리는지 판단하려 들지 말고, **판단할 수 있는 형태로만**
옮겨라.

실제로 있었던 일이다. 어느 뉴스레터가 엔-달러 저점을 "155엔대"라고 썼는데
한국은행 일별 매매기준율은 157.32 였다. 잘 쓴 글이라고 숫자가 맞는 것은
아니다. 네 일은 그 숫자를 믿는 것이 아니라 확인할 수 있게 적는 것이다.

## claim_type — 무엇에 관한 말인가

하나만 고른다.

| 값 | 언제 | 예 |
| --- | --- | --- |
| `numeric_fact` | 숫자·지표 | 코스닥이 6.97% 올라 854.47로 마감했다 |
| `event_fact` | 일어난 일 | 미국과 일본이 공동 개입했다 |
| `market_observation` | 시장 관측 | 기관이 코스닥을 순매수했다 |
| `policy_fact` | 정책·제도 | 20일부터 단기 육아휴직이 시행된다 |
| `corporate_fact` | 기업 실적·공시 | 알테오젠이 흑자 전환했다 |
| `causal_claim` | 인과 | AI 투자 증가가 메모리 부족을 불렀다 |
| `interpretation` | 해석 | 성장주 심리가 회복되고 있다 |
| `forecast` | 전망 | 9월 금리 인하 가능성이 커졌다 |
| `opinion` | 의견·권고 | 신중한 접근이 필요하다 |

**숫자가 없어도 인과를 지목하면 주장이다.** 스터디에서 갈리는 지점은
"무엇이 얼마"보다 "무엇 때문에"인 경우가 많고, 그건 가격 데이터로는
절대 알 수 없다. 버리지 마라.

## verification — 어떻게 확인하는가

"확인 가능한가"를 참/거짓으로 답하지 마라. **어느 경로로 가야 하는지**를
고른다.

| mode | 뜻 |
| --- | --- |
| `direct_data` | 아래 어댑터로 바로 맞춰볼 수 있다 |
| `primary_source` | 원문을 찾아야 한다. 공시·보도자료·법령 |
| `multi_source_research` | 여러 근거를 모아야 판단이 선다 |
| `interpretive` | 검증 대상이 아니라 논의 대상이다 |
| `future_tracking` | 아직 안 일어났다. 지켜볼 일이다 |
| `not_researchable` | 다룰 것이 없다 |

`targets` 는 `direct_data` 일 때만 채운다. `adapter` 는 다음 중 하나:
`ecos`(환율·금리·물가·지수) `krx`(종목 시세·수급) `dart`(기업 공시)
`fred`(미국 거시) `bls`(미국 고용·물가 원문) `fed`(연준 결정)

**닿지 않으면 솔직히 다른 mode 를 고르고 targets 를 비워라.** 미국 CPI,
국민연금 운용, 앱 사용자 수는 지금 어댑터로 안 닿는다. 닿는 척하지 마라.

## source_span — 원문 그대로

- 블록 원문에서 **끊기지 않고 이어지는 한 구절**을 그대로 복사한다.
- 떨어진 두 곳을 `...` 이나 `/` 로 이어 붙이지 마라. 그렇게 하면 원문에
  없는 문장이 만들어진다. 한 곳만 골라라.
- 표현을 다듬지 마라. 조사 하나도 바꾸지 마라.
- 원문에 없으면 그 주장을 아예 넣지 마라.

이 구절이 원문에 실제로 있는지 코드가 대조한다. 지어내면 잡힌다.

## 사실과 해석을 나눠라

한 문장에 둘이 붙어 있는 경우가 많다.

> "기관 순매수 1조 2,240억 원이 유입되며 **투자 심리 회복을 보여준다**"

앞은 `claim`, 뒤는 `interpretation`. 해석을 버리지 않는 이유는 그것이
곧 스터디에서 검증할 통념이기 때문이다.

## 무엇을 남기고 무엇을 버리나

개수는 정하지 않는다. 대신 **기준**이 있다.

> 이 주장이 틀렸다면 이 글의 결론이 달라지는가?

달라지면 넣는다. 안 달라지면 버린다. 이게 유일한 기준이다.

### 버려야 할 것

**배경 설명.** 제도가 무엇인지, 그 회사가 무슨 일을 하는지 알려 주는
문장은 주장이 아니라 각주다.

> "비자 컨설팅&애널리틱스는 비자의 결제 컨설팅 조직이다"
> "근로기준법은 주 52시간을 넘기지 못하도록 규제하고 있다"

**규모를 자랑하는 곁가지.** 숫자가 있어도 글의 결론과 무관하면 버린다.

> "비자 네트워크에서는 하루 평균 9억 건의 거래가 오간다"

**아무 때나 참인 일반론.**

> "변동성을 감안해 투자 전략을 세우는 것이 중요합니다"

**같은 사실의 다른 표현.** 한 번만 넣는다.

### 쪼개지 마라

"AI 투자가 늘어 메모리가 부족해졌다"는 인과 주장 **하나**다.
"AI 투자가 늘었다" + "메모리가 부족하다" + "전자가 후자를 불렀다"
셋이 아니다. 쪼개면 개수만 늘고 아는 것은 그대로다.

### 감

잘 쓴 뉴스레터 한 문단이 걸고 있는 것은 보통 두셋이다. 열 개가 나온다면
배경 설명까지 옮기고 있는 것이다. 시황표처럼 지수가 나열된 블록은 예외다.

뽑을 것이 없으면 빈 목록이 맞다. 억지로 채우지 마라.

## 출력 예

```json
{
  "claims": [{
    "headline": "코스닥 10일간 30% 상승",
    "claim": "코스닥 지수는 최근 10일 동안 30% 이상 상승했다.",
    "claim_type": "numeric_fact",
    "source_span": "코스닥 지수가 최근 10일 동안 30% 이상 상승하며",
    "interpretation": "",
    "verification": {
      "mode": "direct_data",
      "targets": [{"adapter": "ecos", "purpose": "코스닥 일별 지수"}]
    }
  }]
}
```
